기존 저장소에서 먼저 `git status --short --branch`로 집 PC의 미완성 변경을 확인한다. 변경이 있으면 보존한 뒤 진행한다. 아래 명령을 한 줄씩 실행하고 실패하면 다음 단계로 넘어가지 않는다.

```powershell

git switch feature/real-data-backtest
git pull --ff-only origin feature/real-data-backtest
```

원격에만 있는 브랜치의 자동 추적이 꺼져 있으면 `git switch --track origin/feature/real-data-backtest`를 사용한다. 집 PC에 같은 이름의 다른 커밋이 있거나 fast-forward가 불가능하면 비교 후 처리하고 강제 push/reset으로 맞추지 않는다. 브랜치 간 병합은 PR로 한다.

새 클론이면:

```powershell

Set-Location .\invest-lab
```

`.env`는 사용자가 직접 별도 이전한다. 기존 파일을 임의로 덮어쓰지 않는다. 키·계좌·토큰을 출력하거나 Git에 추가하지 않는다.

### 새 PC에서 복원

먼저 저장소 루트에서 Python 환경을 준비한다. 프론트는 화면 작업을 할 때 `frontend/`에서 `npm.cmd ci`로 설치한다. 가상환경/의존성 폴더를 기존 PC에서 복사하지 않는다.

```powershell
uv sync --project backend --frozen
$env:PYTHONUTF8 = '1'
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new($false)
```

압축파일을 저장소의 `.local/imports/invest-lab-research-20260929.zip`에 복사한다. 해시를 이 문서와 대조한 다음, 앱과 작업자가 종료된 상태에서 **새 임시 폴더**로 압축을 푼다.

```powershell
$archive = Join-Path $PWD '.local\imports\invest-lab-research-20260929.zip'
Get-FileHash -LiteralPath $archive -Algorithm SHA256
$staging = Join-Path $PWD '.local\imports\research-20260929'
if (Test-Path -LiteralPath $staging) { throw '이미 있는 임시 폴더입니다. 새 경로를 사용하세요.' }
Expand-Archive -LiteralPath $archive -DestinationPath $staging
& .\backend\.venv\Scripts\python.exe (Join-Path $staging 'verify-bundle.py')
if ($LASTEXITCODE -ne 0) { throw '연구 자료 무결성 검사가 실패했습니다.' }
```

정상 검증 후 네 폴더를 복사한다. 아래는 기존 같은 이름의 연구 폴더를 덮어쓰지 않도록 먼저 전체 대상을 검사한다. 이미 있으면 해시와 내용을 비교해 수동으로 보존/정리한 뒤 진행한다.

```powershell
$researchFolders = @('backtest-20260929', 'engine-review-20260929', 'sell-engine-v3-20260929', 'sell-review-20260929')
foreach ($folder in $researchFolders) {
    if (Test-Path -LiteralPath (Join-Path $PWD ".local\$folder")) {
        throw "기존 연구 폴더를 먼저 비교하세요: $folder"
    }
}
foreach ($folder in $researchFolders) {
    Copy-Item -LiteralPath (Join-Path $staging ".local\$folder") -Destination (Join-Path $PWD '.local') -Recurse
}
```

기존 증거 JSON에 남은 사무실 절대 경로는 당시 기록이다. 새 PC 명령은 저장소 루트의 상대 경로를 사용한다. 해시를 맞추려고 과거 manifest를 수정하지 않는다.

## 4. 재개 확인과 재현

기본 코드 검사에는 키나 외부 계좌 연결이 필요 없다.

```powershell
uv run --project backend --frozen ruff check backend/src backend/tests scripts
uv run --project backend --frozen ruff format --check backend/src backend/tests scripts
uv run --project backend --frozen pytest backend/tests -q
```

최신 자료/결과는 다음 파일부터 읽는다.

- `.local/sell-engine-v3-20260929/data/action-review.json`: 수용한 기업행동과 미확인 항목.
- `.local/sell-engine-v3-20260929/run-05/manifest.json`: 데이터 해시·기간·18개 전략 설정·실행 코드 해시.
- 같은 폴더의 `summary.json`, `data-quality-diagnostics.json`, `cached-replay-verification.json`: 지표, 데이터 제약, 기준선 재생 일치 증거.
- `baseline-5.json.gz`, `stagnation-5.json.gz` 등: 각 설정의 거래·평가액·진단 전체. JSON 숫자의 `return=0.0255`는 2.55%다.

기존 결과를 읽는 데 전체 백테스트를 다시 돌릴 필요는 없다. 재현이 필요하면 우선 기준선 하나를 **새 출력 폴더**로 재생한다.

```powershell
$env:PYTHONPATH = 'backend/src'
$env:PYTHONUTF8 = '1'
backend\.venv\Scripts\python.exe scripts\compare_portfolio_policies.py --only baseline-5 --output .local/home-replay-20260929 --feature-cache .local/sell-engine-v3-20260929/indicators.json.gz
```

18개 전체 비교는 `--only baseline-5`를 빼고 다른 새 출력 폴더를 지정한다. 지표 캐시가 데이터/코드 해시 불일치로 거절되면 기존 캐시를 수정하지 말고 `--feature-cache`를 생략해 다시 계산한다. 실행 시간이 늘어난다.

**중요한 입력 의존성:** 이 실행기는 최신 `data/dataset.json.gz`뿐 아니라 `.local/engine-review-20260929/verified/corrected.json.gz`의 `strategy` 설정을 읽는다. 이전 결과 +3.0666%를 재사용하는 것이 아니다. 데이터셋 하나만 가져오면 이 명령을 그대로 실행할 수 없으므로 네 폴더를 함께 보존한다.

수집/자료 준비 스크립트는 2026-09-29의 고정 날짜 연구용이다. 새 PC 확인을 위해 무조건 수집/`prepare_dart_actions.py`를 다시 실행하지 않는다. 새 원문/정정 수집은 데이터와 결과를 바꿀 수 있으므로 기존 증거를 보존한 별도 연구로 진행한다. `.local/.../verify_cached_run.py` 역시 기존 검증 JSON을 쓰므로 보존된 결과를 읽기만 할 때 실행하지 않는다.

## 5. 검증과 포장 기록

2026-09-29 인계 준비 시 이 PC에서 다시 확인했다.

- 백엔드 전체 **299개 테스트 통과**, 기존 Starlette/httpx 사용 중단 예정 경고 1개.
- Ruff 검사/포맷 검사 통과: `backend/src`, `backend/tests`, `scripts`의 Python 76개 파일.
- 격리 OpenAPI 내보내기 및 프론트 `api:check` 통과. API 생성 파일 변경 없음.
- 인계 관련 문서 8개의 로컬 링크와 PowerShell 예시 45개의 구문 검사 통과. 현재 도메인 코드 해시가 앞서 기준선 재생을 검증한 코드와 일치함을 확인했다.
- 화면 변경 없음. 이번 인계에서 프론트 UI/브라우저 테스트와 실제 KIS 주문 검증을 새로 실행하지 않았다.
- 18개 전체 백테스트는 이번 인계에서 반복하지 않았다. 보존된 `run-05` 보고서와 재현 증거를 전달한다.

연구 압축파일은 3,809개 연구 파일과 manifest/검증기/설명서로 구성된다. 키 값을 압축 해제한 gzip/ZIP 내용까지 대조해 포함되지 않았음을 검사했고, 모든 항목의 SHA-256과 ZIP 무결성을 확인했다. 별도의 새 폴더에 `Expand-Archive`로 실제 복원한 뒤 `verify-bundle.py`로 3,809개 파일을 다시 검증했다. 커밋 대상에서도 현재 `.env`의 키·계좌번호·HTS 식별자 값이 포함되지 않았음을 확인했다.

| 항목 | 값 |
| --- | --- |
| 파일명 | `invest-lab-research-20260929.zip` |
| 압축 용량 | 265,242,929 bytes (약 265 MB / 253 MiB) |
| SHA-256 | `e268d32feac9e1e7dc7f24343d555b3b4cfbcd0790862132a91848c0b9599205` |
| 최신 데이터셋의 내용 해시 | `a0e0708a464273f756bcb048f4356f8179def10621f09b845da8016036e2e26e` |

마지막 행은 `content_hash`로 계산한 JSON 내용 해시이며 gzip 파일 자체의 SHA-256과 다르다. 파일별 바이트 해시는 압축 내부 `research-manifest.json`을 따른다. 같은 폴더에 ZIP의 `.sha256` 파일도 보관했지만, 이 문서에 해시가 있으므로 전달 시에는 ZIP 하나로 충분하다.
