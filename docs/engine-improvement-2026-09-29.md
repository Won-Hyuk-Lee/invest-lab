# 투자 엔진 1차 개선 및 재검증 — 2026-09-29

기존 코스피 눌림목 탐색 결과와 외부 검토를 바탕으로 재생 시점, 주문 수명, 수량 근거, 데이터 누락 분모를 수정했다. 전략의 RSI·ATR 배수·위험 예산·보유 수 상한은 기존 설정을 유지했다. 실행 계약을 바꾼 결과이므로 수정 후 수익률 변화는 전략 최적화 성과로 해석하지 않는다.

**현재 판정: 엔진 1차 수정과 전후 재생은 완료했지만 성과 검증은 차단 상태다.** 재생에서 나온 +3.07%에는 `002630`의 감자 수량 미반영 거래가 포함되어 있어 유효한 투자 성과로 사용할 수 없다. 아래 수치는 수정 효과를 추적하기 위한 원시 계산 결과다.

## 고정한 일봉 실행 계약

엔진 버전은 `daily-precommitted-v2`다.

1. KRX 정규장 09:00 KST 개장과 18:00 KST 장후 판단을 구분한다. 이 시각은 연구 가정이며 특별 개장일 달력과 역사 공개 시각은 아직 검증되지 않았다.
2. 당일 장후에 확인한 유니버스와 지표로 다음 거래일 후보를 만든다. 상위 20개 안에서 우선순위대로 가용 자금·보유 자리·노출을 예약한다.
3. 매수 상한가는 신호 종가 × `(1 + max_gap_pct / 100)`이다. 수량은 이 상한가와 비용을 기준으로 장후 확정한다. 이후 시가가 달라졌다고 수량을 늘리지 않는다.
4. 기존 포지션과 신규 주문 예약을 합산한다. 예정 매도의 대금과 노출 감소는 미리 반영하지 않는다. 청산 예정 포지션의 자리는 계획에 반영하되 실제 매도가 실패하면 개장 시 보유 수 상한으로 후속 매수를 거절한다.
5. 다음 날 실제 시가에 가정 슬리피지를 더한 가격이 상한가 이하면 확정 수량을 체결한다. 상한가를 넘거나 거래불가이면 해당 매수는 만료된다. 장중에 가격이 상한가를 통과했다는 이유로 추가 체결하지 않는다.
6. 하락 갭은 상한가 매수 주문을 취소하는 조건이 아니다. 기존의 양방향 3% 갭 필터와 의미가 다르다. 일봉에는 호가 대기열·개장 경매 수량·과거 호가단위가 없어 실제 체결 보장을 뜻하지 않는다.
7. 매도는 매수보다 먼저 시도한다. 거래정지 중 미체결이면 최초 의도를 유지한다. 배당·분할·상폐 정산은 공급된 사건 원장에 따르고, 예정 매수의 분할 수량·가격 조정 및 알려진 상폐 매수 취소도 처리한다.
8. 일 손실 기준은 전일 평가액 대비 당일 종가 평가액으로 다음 진입 계획을 중단하는 조건이다. 장중 손실의 절대 상한 또는 자동 전량 청산이 아니다.
9. `intraday_stop=true`일 때만 일봉 저가·시가 기반의 보수적 손절 모의를 수행한다. 원래 비교 설정은 `false`다. 종료일 미체결 주문과 보유는 결과에 보존한다.

기업행동이 장 시작 이후 알려졌는데 그날 시가의 수량이나 권리에 영향을 주는 경우, 소급 적용하지 않고 자료 계약 오류로 중단한다. 회고 수집의 `ingested_at`이 과거보다 늦다는 이유만으로 역사 자료를 전부 거절하지는 않는다. 시점 가시성의 기준은 `available_at`이며, 동일 공개 시각 수정본의 선택에는 수집 시각을 사용한다.

## 자동운용과의 관계

자동운용은 기존의 `quote_observed_first_30_minutes` 방식을 유지한다. 현재 시세로 주문을 판단하는 방식이며, 이 일봉 기준선과 같은 체결 모델로 보지 않는다. 관리 중 보유의 청산은 별도 `quote_observed_managed_exit`로 기록한다. 백테스트 결과에 `runtime_equivalent=false`를 명시한다.

`position_size_details()`는 연구와 자동운용이 공유한다. 기존 `size_position()` 호출은 수량만 반환하는 호환 래퍼로 유지한다. 자동 주문 문맥과 로컬 `sizing_decisions`에는 한도별 허용 수량, 결정적 제한, 위험 예산, 예상 손절 위험, 비용 예약액, 계산에 쓴 가격과 자산을 저장한다. 기존 API 스키마는 변경하지 않았다.

이번 작업은 일봉 기준선과 실제 관측 운용의 차이를 명시한 단계다. 분봉·호가 기록을 이용한 동일 관측값 재생과 실제 장중 모의 체결 검증은 남아 있다. 주문 활성화 설정은 변경하지 않았다.

## 재현과 산출물

원본 연구 데이터는 `.local/backtest-20260929/krx/`에 그대로 둔다. 수정 전 소스·결과 7개와 파일 해시는 `.local/engine-review-20260929/baseline/`에 보존했다. 비교 산출물의 입력·코드·결과 해시와 실행 소스 스냅샷은 각 실행 폴더에 남긴다. 비밀값과 시장 원문은 Git에 넣지 않는다.

```powershell
# 저장소 루트, 기존 원문과 KIS 마스터가 있는 PC에서 실행
$env:PYTHONPATH = 'backend/src'
$env:PYTHONUTF8 = '1'
backend\.venv\Scripts\python.exe scripts\research_krx_backtest.py build --output-directory .local/engine-review-20260929/data
backend\.venv\Scripts\python.exe scripts\review_krx_backtest.py --output .local/engine-review-20260929/verified
backend\.venv\Scripts\python.exe scripts\audit_krx_replay_quality.py --dataset .local/engine-review-20260929/data/dataset.json.gz --result .local/engine-review-20260929/verified/corrected.json.gz --output .local/engine-review-20260929/verified/quality-audit.json
```

이미 완료된 결과는 입력·코드·결과 해시가 일치할 때만 재사용한다. 코드나 입력을 변경한 실험에는 다른 `--output` 폴더를 지정한다. 이 비교 명령은 인증키를 읽거나 외부 브로커를 호출하지 않는다.

마지막 품질 감사는 현재 데이터에서 의도적으로 종료 코드 2를 반환한다. 이는 검증 차단이며 실행 성공이나 성과 승인으로 취급하면 안 된다. 가격 급변 기준은 40%로, 전일부터 보유한 종목을 당일 시가에 매도했어도 점검하고 거래불가 평가가격의 급변도 확인한다. 급변이 없다고 기업행동 누락이 없다는 뜻은 아니며, 급변만으로 분할 비율을 추정하거나 가격을 보정하지 않는다. 현재 감사는 기업행동 원장이 빈 탐색 결과에 한정되며, 사건을 채운 뒤에는 권리·단주·정산까지 검증하는 별도 원장이 필요하다.
