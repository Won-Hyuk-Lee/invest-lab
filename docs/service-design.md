# 서비스 설계 — 2026-09-25

초기 구현을 설명하는 문서다. 추가 조사와 사용자 선택을 반영한 후속 방향은 [전체 작업 목록](research-roadmap.md), [계산식 후보](indicator-catalog.md), [한투 호출 설계](kis-api-budget.md)를 참고한다. 후속 운용 방식은 일봉 전체 분석 + 후보 10~20개 장중 감시이며, 코스피 상승 추세의 눌림목을 중심으로 ETF 추세와 비교한다.

## 합의한 방향

- 로컬 우선. Python 백엔드와 React/TypeScript/Vite 내부 프론트.
- 헥사고날 아키텍처: 계산과 전략이 증권사, DB, HTTP, 스케줄러에 종속되지 않도록 한다.
- 분석 대상: 코스피 주식과 국내 상장 ETF. 국내 상장 미국 지수 추종 ETF를 포함한다. 코스닥 개별 종목은 초기 범위에서 제외한다.
- 기간 계산은 **거래일 기준**. 수익률 검증을 거쳐 향후 소액 실험을 고려하되 현재 실전 주문 기능은 구현하지 않는다.

## 화면과 계산 정의

대시보드는 주문 가능 현금, 보유 평가액, 현금+보유 평가액, 보유 평가손익을 표시한다. 샘플 계좌의 평단에는 가정한 매수 수수료를 포함한다. 향후 증권사 연결 시 결제 전 잔고, 예수금, D+2 예수금, 주문 가능 금액을 구분해야 한다.

### 등락률과 이동평균

- N거래일 등락률: `(C[t] / C[t-N] - 1) × 100`. N+1개의 유효 종가가 필요하다.
- N일 단순이동평균: 기준일을 포함한 최근 N개 거래일 종가의 산술평균.
- 이동평균 이격도: `(C[t] / SMA[N] - 1) × 100`.
- 연속 하락: 직전 거래일 대비 종가가 낮아진 거래일 수. 보합·상승이면 연속성이 끊긴다.
- 거래량 비율: 기준일 거래량 / 기준일을 제외한 직전 20개 거래일 평균 거래량.
- RSI(14): 첫 14개 변화량의 평균 상승·하락폭으로 초기화하고 이후 Wilder 평활을 적용한다. 전부 보합이면 50, 하락폭 없이 상승만 있으면 100.
- 이력 부족은 `null` / `—`로 표시하며 임의로 0을 채우지 않는다. 초기 모델은 121개 일봉부터 점수를 산정한다.

실제 데이터 연결 시 KRX 거래일과 데이터 누락을 구분하고, 같은 기준의 수정주가로 연속성을 확보해야 한다. 최신 일봉은 장 종료 후 확정된 데이터만 분석한다. 장중 현재가와 전일 확정 지표는 각각의 기준 시각을 표시해야 한다. 현재 fixture는 평일로 만든 가상 거래일이며 실제 한국 휴장일을 재현하지 않는다.

### 상태 분류

- 상승 추세: 종가 > 30일선 > 90일선 > 120일선.
- 하락 추세: 위 관계의 반대. 나머지는 혼조.
- 과매도 / 과매수: RSI가 설정 기준 이하 / 이상. 기본 30 / 70.
- 연속 하락: 3거래일 이상 연속 하락.
- 반등 조건 충족: 직전 RSI가 과매도 기준+5 이하이고, 기준일 종가 상승과 거래량 1.2배 이상을 동시에 충족.
- 검토 기준 충족: 가중합 점수가 설정한 기준 이상. **자동 주문 트리거가 아니다.**

RSI 과매도나 반등 조건은 수익을 보장하는 예측이 아니다. 같은 종목에 여러 상태가 함께 표시될 수 있다.

### 초기 매수 검토 점수

`점수 = Σ(지표 점수 × 정수 가중치 / 100)`, 가중치 합계는 100.

| 항목 | 0~100으로 환산하는 초기 규칙 | 초기 비중 |
| --- | --- | --- |
| RSI 과매도 | `(과매수 기준 - RSI) / (과매수 기준 - 과매도 기준) × 100`을 0~100으로 제한 | 30 |
| 눌림 | 30일선 대비 -10% 이하이면 100, 0% 이상이면 0, 사이를 선형 환산 | 25 |
| 추세 | 종가>90일선, 종가>120일선, 30일선>90일선, 90일선>120일선 각각 25 | 25 |
| 반등 조건 | 조건 충족 100, 아니면 0 | 20 |

이는 **검증 전 가설**이며 80점은 상승 확률 80%를 뜻하지 않는다. 추세 추종과 역추세 매수는 성격이 다르므로 이후 별도 전략으로 분리해 비교한다. 현재 점수는 기술적 상태 점수다. 기업가치 저평가를 다루려면 실적 발표 시점 기준 PER/PBR/ROE·현금흐름 등 별도 자료가 필요하다.

ETF에는 개별 기업의 가치평가식을 그대로 적용하지 않는다. 추종지수, 보수, 거래량·호가 스프레드, 괴리율, 추적오차, 환헤지 여부를 별도 항목으로 추가한다. 동일 미국 지수를 추종하는 여러 ETF의 보유 비중은 합산해 노출을 관리해야 한다.

지표 정의 참고: [Fidelity RSI](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/RSI), [Fidelity SMA](https://www.fidelity.com/learning-center/trading-investing/technical-analysis/technical-indicator-guide/sma). 위 가중합과 반등 조건은 이 프로젝트의 실험용 규칙이다.

## 다음 구현 순서

1. **한투 조회와 데이터 저장**: 백엔드 전용 인증, 토큰 재사용, 호출 속도 제한, 종목 마스터/거래일, 수정주가 일봉 수집, 누락 검증. 먼저 관심 종목으로 검증한 뒤 전체 코스피와 ETF로 확대한다.
2. **증권사 모의계좌**: 로컬 장부와 별도 계좌 유형으로 다루고 실제 잔고/주문 가능 현금, 매수·매도, 미체결·부분 체결·취소를 조정한다. 단순 HTTP 재시도가 중복 주문을 만들지 않도록 주문 조회와 대조한다.
3. **과거 검증**: 시간순 학습/검증/최종 테스트 분리, walk-forward, 다음 거래일 체결, 수수료·세금·슬리피지·분배금 가정, 상장폐지 및 과거 구성종목 반영. 미래 정보를 전략 계산에 전달하지 않는다.
4. **모의 운용**: 하루 종가 기준으로 우선 검증. PC가 꺼진 날의 누락과 재시작을 기록하고, 전략 버전·입력 데이터 시각·신호·주문·체결을 연결해 보관한다.
5. **실전 전환 검토**: 한 달 모의 결과는 운영 안정성 확인 자료로 삼는다. 승률뿐 아니라 누적 수익, 최대 낙폭, 손익비, 거래 횟수, 벤치마크 대비 성과를 함께 평가한다. 실전 브로커는 별도 어댑터와 명시적 활성화 절차가 필요하다.

## 인프라 교체 경계

현재 `MarketData`, `StrategyRepository`, `PortfolioRepository`, `Clock` 포트를 조립한다. 외부 주문 기능을 붙일 때는 시세와 분리된 `Broker` 포트를 정의한다. HTTP와 배치 진입점은 같은 유스케이스를 호출하도록 확장한다.

헥사고날 구조는 교체 범위를 줄여주지만 모든 호스팅 환경의 Python 지원, 파일 저장, 장기 실행 제약을 없애지는 않는다. 원격 운영 시 외부 인증, 비밀 관리, 영속 DB, 작업 스케줄링을 별도로 구성한다.
