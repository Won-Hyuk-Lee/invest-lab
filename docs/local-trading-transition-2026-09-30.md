# 로컬 매매 도구 전환·검증 기록

2026-09-30, Windows 로컬 작업 기준이다. 현재 실행 계약은 [README](../README.md)와 [로컬 매매 안내](local-trading.md)를 따른다.

## 변경한 방향

AI/외부 스크립트가 종목·방향·수량·가격·근거를 판단한다. 앱은 구조화된 JSON을 받아 한도 검사, 주문 큐, 전송, 체결·계좌 대조와 복구를 담당한다. AI 모델 호출이나 수익 전략을 내장하지 않는다.

- 기본 `execution` 프로필은 기존 연구 전략의 자동 운용과 연구 작업을 실행하지 않는다. 기존 자료·소스는 보존했다.
- 기본 화면을 계좌/보유, 외부 연결 설정, 판단 JSON 검사/제출, 최근 판단 콘솔로 바꿨다.
- API/CLI는 같은 서비스·판단 ID를 사용한다. 중복 등록을 방지하고 재요청으로 큐를 다시 만들지 않는다.
- 만료, 허용 종목, 주문 금액, 보유 비중, 최신 시세/잔고, 장 시간, 미확정 주문·대조 상태를 검사한다. 설정 변경/중지는 대기 중 판단에도 적용한다.
- 실전 국내 현금 주문용 `kis_live`를 추가했다. 모의와 키/주소/토큰 범위/장부를 분리하고 주문은 기본 중지다. 매수·매도·정정·취소와 REST 체결 대조를 지원한다.
- 복원 시 외부 주문을 중지하고 기존 주문의 확인/격리 절차를 유지한다.

## 실행한 확인

검증 데이터는 `.local/verification/`의 별도 상태/DB를 사용했다. 사용자의 기존 운용 DB와 `.env`를 변경하지 않았다.

| 확인 | 결과 |
| --- | --- |
| `pytest backend/tests -q` | 426개 통과 |
| 외부 판단/실전 브로커 관련 회귀 | 기본 중지, ID 충돌·중복, 만료, 큐 실행 전 중지/한도 재검사, 응답 유실, 모의/실전 분리 통과 |
| 실전 HTTP 계약 | MockTransport로 공식 호스트/TR, 매수·매도·정정·취소, 잔고/가능액/조회, POST 재전송 방지 확인 |
| Python 스타일/계층 | Ruff check·format 및 전체 테스트의 아키텍처 검사 통과 |
| 프론트 단위 검사 | 11개 통과 |
| 프론트 빌드/OpenAPI 계약 | 통과 |
| Playwright 브라우저 회귀 | 7개 통과, 접근성·작은 화면·기존 주문 복구 포함 |
| 실제 로컬 API+작업자+브라우저 | JSON 매수→체결→매도, 동일 ID 재요청, 잘못된 JSON, 금액 초과, 중지 후 검사만 허용 확인 |
| 컴파일한 화면 | 매매/주문/운영/설정의 직접 진입·새로고침 4개 경로 통과, 쓰기 요청 없음 |
| CLI | 설정→검사(미전송)→등록→작업자→같은 ID의 체결 조회 확인 |

FastAPI 테스트에서 기존 httpx/Starlette 호환성 deprecation 경고 1개가 나온다. 테스트 실패는 아니다.

## 실제 계좌에서 아직 확인하지 않은 부분

실전 키의 권한, 실제 계좌 조회, 장중 접수/체결/정정/취소, 브로커 비용과 정정 회계는 실제 계좌에서 검증하지 않았다. 외부 모의 주문도 전송하지 않았다. 로컬 성공을 실제 증권사 체결 성공으로 해석하지 않는다.

실전 준비는 `KIS_LIVE_*` 설정 후 `doctor`와 **읽기 전용** `broker-read-check`부터 진행한다. 국내 종목 마스터·검증된 개장 달력과 계좌 대조를 준비하고 실전 주문을 사용할 때만 주문 활성화와 외부 자동 주문/신규 매수를 허용한다. 절차와 명령은 [실전 연결 안내](local-trading.md#실전계좌-연결)에 있다.

미국 상장 ETF 직접 주문, 신용·미수·공매도·NXT/SOR, 실전 WebSocket 체결통보는 구현 범위에 포함하지 않는다. 실전은 분 단위 및 제출 직후 REST 대조를 사용한다.

코드/공유 문서는 현재 `feature/real-data-backtest` 브랜치에서 작업 단위별로 커밋한다. `.env`, 실행 DB, 토큰 캐시, 큰 검증 산출물은 Git에 포함하지 않는다. 커밋·푸시는 2026-09-30의 후속 사용자 지시에 따라 진행한다.
