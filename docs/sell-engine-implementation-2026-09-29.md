## 비교 계획

기간은 2025-01-02~2026-09-23, 초기 자금 1천만원, 동일한 자료·수수료·매도세·슬리피지를 사용한다. 기업행동이 누락된 기존 +3.0666%는 개선 성과로 인정하지 않는다.

1. 기업행동 보정 후 기존 5종목·회복 전량 청산을 기준선으로 재생한다.
2. 5/10/20종목을 전체 손절 위험 상한 1.25%로 맞춰 비교한다. 거래당 0.25%를 유지하고 전체 위험 상한을 확대하는 비교는 별도 표시한다.
3. 10종목에서 회복 전량/회복 후 추적/절반 회수 후 추적을 비교한다. 이후 정체 청산 및 보유 연장을 분리한다.
4. 같은 조건의 교체 OFF/ON 비교. 하루 1쌍, 최소 보유 3세션, 재진입 대기 3세션, 신규 상위 85백분위, 보유 60백분위 이하, 차이 20 이상, 비용 상한 50bp를 초기 가설로 사용한다.
5. 추가 가설로 초기 손절 폭 상한 15%, 최대 보유 5/10/20세션, 위험 초과 시 감축을 비교한다. 결과를 보고 선택한 설정은 사후 선택이라고 표시한다.

일봉 교체 매수는 매도 체결일 장후 재평가 후 다음 시가가 가장 빠른 체결 시점이다. 분할청산은 1주면 전량, 홀수면 내림(최소 1주)으로 고정한다. 배당·단주 지급일 미확인은 현금으로 당겨 쓰지 않는다. 이 기간은 이미 여러 번 확인했으므로 미사용 검증 구간으로 표현하지 않는다.

## 구현 계약과 기존 설정 호환

`StrategyRules`의 기존 값은 유지한다. 새 정책은 명시한 전략 버전에 설정해야 적용되며, 사용자 운용 DB의 배포 버전이나 주문 활성화 상태를 이 작업에서 변경하지 않는다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `max_positions` / `candidate_limit` | 5 / 20 | 보유·예약 종목 수와 분석 후보 수를 분리 |
| `exit_policy` | `recovery` | `recovery`, `trail`, `partial_trail` 중 선택 |
| `trailing_atr` / `recovery_sell_pct` | 2 / 50 | 회복 후 최고 종가에서 2ATR 보호, 부분 회수 비율 |
| `holding_extension_sessions` / `stagnation_sessions` | 0 / 0 | 보유 연장 및 정체 조기청산은 기본 비활성 |
| `min_progress_r` | 0.25 | 정체 청산 시 초기 위험 대비 최고 종가 진전 기준 |
| `max_initial_stop_pct` / `max_open_risk_pct` | 100 / 100 | 초기 손절 폭·계좌 손절 위험 제한은 기존 호환값; 비교에서는 15%, 1.25% 등 명시 |
| `rebalance_risk` / `rotation_enabled` | false / false | 위험 초과 감축·기회 교체는 명시적 실험 옵션 |

- 공통 정책은 `domain/portfolio_policy.py`; 실제 체결 수명주기 반영은 `application/execution.py`; 런타임 교체 상태는 `adapters/rotation_execution.py`다.
- 잔여 주수·부분 청산 원가·초기 위험·손절선·최고 종가를 함께 유지한다. 매도 체결이 손절선을 덮어쓰지 않는다. 전량 청산 후 매수는 새 진입일과 새 포지션 ID를 만든다.
- 종가를 보고 올린 추적 손절은 이후 세션부터 적용한다. 부분 회수 목표는 의도 생성 시 고정하고, 실제 누적 체결을 빼서 재시작 후 중복 매도를 막는다. 만기/손절은 부분 회수나 교체보다 우선한다.
- 전량 미체결 매도로 매도 가능 수량이 0이어도 보호 청산 의도를 저장한다. 실제 매도 가능 수량과 주문 대조를 거쳐 제출한다.
- 교체 매도 부분 체결은 슬롯을 비우지 않는다. 수동 보유 잔량, 결과 불명, 취소 미확인은 슬롯 해제로 보지 않는다. 후보 소멸/가격 갭 변화 시 교체를 취소하거나 현금을 유지한다. 교체 매도 불명 이후에는 같은 호출에서 신규 매수를 진행하지 않는다.
- 계좌 손절 위험은 현재 평가가와 보호선의 차이에 실제 수량을 곱하고 미체결 매수 위험을 더한다. 손절선이나 미체결 위험을 모르면 0으로 간주하지 않고, 이 제한이 활성화된 신규 매수를 막는다. 이 계산은 갭·동시 손실을 포함하는 최대 손실 보장이 아니다.
- 런타임 상태는 기존 문서 저장소의 `allocation`, `exit_assessment`, `exit_intent`, `rotation_pair`, `rotation_cooldown`으로 영속화한다. SQL 테이블 마이그레이션은 없다.

### 기존 보유와 실제 운영 경계

이전 `allocation`에 새 필드가 없다고 과거 진입일·원가·초기 위험을 새 값으로 덮어쓰지 않는다. 진입일이 없으면 확인 사유를 남기고 자동 청산 판단에서 제외하며, 원가가 없는 기존 보유에 추가 매수가 체결되면 `ledger_incomplete`로 표시한다. 고급 매도 정책을 기존 보유에 적용하기 전 체결 원장으로 진입일·잔량·보호선·원가를 대조해야 한다. 새로 0→양수가 되는 자동 체결은 완전한 새 수명주기를 만든다.

실제 KIS 계좌의 감자/분할 수량을 자동 대사·승인하는 기능까지 구현한 것은 아니다. 이번 기업행동 처리는 연구 재생용이며, 운영 계좌와 내부 수량이 달라지면 기존 대조 차단을 유지한다. 재시작/부분 체결/취소/호가 변화 검증은 격리된 `local_simulation`에서 수행했고 실제 KIS 주문 검증으로 표현하지 않는다.

원천의 일봉 공개 시각은 18시 추정이고 DART는 공시일 종료 시점으로 보수적으로 설정했다. 실제 과거 수집 시각을 복원한 PIT 자료가 아니다. 확정된 최신 공시/상장 수량으로 사건의 실행 여부를 사후 대조한 점도 한계다. 과거 시점의 조건 변경 가능성과 누락 자료를 별도 해결하기 전 실전 성과 검증 게이트를 통과시키지 않는다.

저장소 루트에서 기존 Python 환경을 사용한다. 비교 출력에는 새 디렉터리를 지정해야 한다.

```powershell
$env:PYTHONPATH = 'backend/src'
$env:PYTHONUTF8 = '1'
backend\.venv\Scripts\python.exe scripts\collect_dart_actions.py --originals
backend\.venv\Scripts\python.exe scripts\collect_dart_gap_evidence.py
backend\.venv\Scripts\python.exe scripts\prepare_dart_actions.py
backend\.venv\Scripts\python.exe scripts\compare_portfolio_policies.py --output .local/sell-engine-v3-new-run --feature-cache .local/sell-engine-v3-20260929/indicators.json.gz
backend\.venv\Scripts\python.exe scripts\report_portfolio_comparison.py --run .local/sell-engine-v3-new-run
```

수집/준비는 고정 날짜 연구 스크립트이며 현재 날짜의 자동 거래 파이프라인이 아니다. 같은 입력으로 재생할 때는 이미 보존한 데이터와 원문을 사용한다. 데이터셋 해시·실행한 도메인 코드 해시·전략별 값은 비교 폴더의 `manifest.json`, 결과 해시는 `summary.json`에 기록한다. `.local`은 Git에 없으므로 다른 PC 재현에는 별도 데이터 백업이 필요하다.

`--feature-cache`는 전략 판단 전 기술·재무 지표만 JSON 압축 파일로 저장한다. 데이터 해시와 지표 함수/의존 코드 해시가 다르면 재사용을 거절한다. 주문, 보유, 손익, 위험 제한은 설정마다 새로 재생한다.
